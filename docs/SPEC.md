# SPEC — требования CallMyPromts

> Статус: **действует с 2026-09-05**. Версия 1.0.
> Правила выше этого документа: [`docs/RULES.md`](docs/RULES.md:1).
> Границы модулей: [`arch.yaml`](arch.yaml:1). Связь требование → тест: [`trace.csv`](trace.csv:1).

## 0. Задача

Заменить три расходящиеся копии библиотеки промптов и ручной конвейер из пяти скриптов
одним приложением: горячая клавиша → окно выбора → вставка. Плюс журнал буфера обмена,
из которого любая запись сохраняется в библиотеку как промпт.

Доказанная разведкой проблема (v1–v4):

| Факт | Подтверждение |
|---|---|
| три копии библиотеки, тексты разошлись | MD5: 26 из 31 файлов различаются; пересечение с ClipClip = 0 |
| актуальные правки живут в ClipClip, а не в `.md` | 22 файла в `Documents\ClipClip\Saved Clips\Промпты` |
| доставка не работает вовсе | espanso не запущен, AHK не запущен, Punto перехватывает хук |
| `fill.py` молча затирает правки | слово `TODO` в тексте = признак заглушки; `p-parse.md` совпадает с `.bak` |
| файл вне `items.py` невидим | `:c-nocode` создан, в `base.yml` отсутствует |
| счётчики использования никогда не работали | `used: 0` у всех 26 промптов |
| один битый `.md` ломает все 26 триггеров | сборка одного `base.yml` без YAML-валидации |

## 6. Локальный API — модуль `server`

| ID | Требование | Критерий готовности | Статус |
|---|---|---|---|
| REQ-API-BIND | Слушает только `127.0.0.1`, порт настраиваемый | подключение с внешнего адреса невозможно | done |
| REQ-API-AUTH | Каждый запрос требует токен из `state/token` | запрос без токена → 401 | done |
| REQ-API-PROMPTS | `GET /api/prompts`, `GET /api/prompt/:id`, `POST /api/prompt`, `POST /api/prompt/:id/used` | контрактные тесты | done |
| REQ-API-CLIPS | `GET /api/clips`, `POST /api/clips/:id/promote`, `DELETE /api/clips/:id` | контрактные тесты | done |
| REQ-API-SYSTEM | `GET /api/system` — состояние сервиса, хоткеев, счётчиков | нет данных → прочерк с причиной | done |
| REQ-API-SETTINGS | `GET/PUT /api/settings` с валидацией | неизвестный ключ → 400 с указанием ключа | done |
| REQ-API-PASTE | `POST /api/paste` — заявка от интерфейса, `GET /api/paste` — забор мостом; заявка одноразовая | мост не забрал → `pasted: false` с причиной | done |
| REQ-API-SERVICE | `GET /api/service` — что можно сделать, `POST /api/service` — остановка и перезапуск в два шага | без `confirm` только план; недоступное действие объяснено | done |
| REQ-API-READY | `/livez`, `/readyz`, `/healthz` без токена; в теле `code_version`, `release_id`, `in_flight` | `/readyz` отдаёт 503 при снятой готовности, `/livez` остаётся 200 | done |

**Почему три адреса, а не один.** Это три разных вопроса, и слитый ответ на них —
источник ложно-зелёного вердикта при обновлении. «Порт занят» и «процесс ответил»
означают только то, что что-то живёт на этом порту: старый процесс, который не умер,
удовлетворяет обоим. Поэтому `/readyz` отдаёт версию кода и номер релиза, а тот, кто
обновляет приложение, обязан сверить оба — совпало, значит запущен именно тот код,
который ставили.

Эндпоинты публичные сознательно: их спрашивают супервизор и скрипт обновления,
которые токена не знают и знать не должны. Секретов в теле нет, и это проверяется по
значениям, а не по словам — тест кладёт в библиотеку промпт с узнаваемым текстом и
требует, чтобы он не появился в ответе.

REQ-API-AUTH обязателен: без токена любая открытая веб-страница прочитала бы журнал
буфера обмена запросом на localhost.

REQ-API-SERVICE появился так же, как REQ-API-PASTE — из найденного разрыва, а не из
проектирования. Три кнопки раздела «Сервис» были в разметке с самого начала
([`UI-SPEC §3.3`](docs/UI-SPEC.md:222)), но за ними не стояло ни обработчика, ни
маршрута: нажатие не делало ничего и ничего не сообщало. Нашёл это тест доступности,
потому что он единственный по этим кнопкам нажимал.

Два решения по существу. Первое: «Запустить» недоступна всегда и с написанной
причиной — страницу отдал сам сервис, значит пока окно видно, он работает, а когда
остановлен, окно не открывается вовсе. Запуск возможен только снаружи, значком в трее.
Второе: остановка и перезапуск требуют подтверждения, как обмен закреплений
([`RULES §6`](docs/RULES.md:1)) — остановка снимает горячие клавиши и слежку, то есть
выключает всё, ради чего программа запущена.

REQ-API-PASTE появился не из проектирования, а из найденного разрыва. Браузер не может
нажать `Ctrl+V` в чужом окне, а мост не слышит событий внутри страницы: прямого канала
между ними нет. Первая версия обходилась событием `deck:paste` в окне браузера — его
никто не слушал, и вставка не происходила никогда, а окно выбора при этом сообщало
«Вставлено». Сервер — единственное общее место, поэтому заявка идёт через него, и
интерфейс показывает результат, который подтвердил мост, а не собственное намерение.

**Оговорка «и доказано, что умеет краснеть» не риторическая.** Гейт с нулевым
покрытием зелёный всегда, и однажды это уже стоило проекту доверия к проверке.
Поэтому [`gates/ready-gate.mjs`](gates/ready-gate.mjs:1) содержит `selfTest()`: он
подкладывает нарушение и требует, чтобы проверка его нашла. Провал самопроверки
делает гейт красным независимо от состояния проекта.

Обратная сторона так же важна. Первая версия гейта покраснела на **верном** коде:
сравнивала положение строк `import`, а не вызовов. Ложное срабатывание опаснее
пропуска — гейт, который краснеет без причины, отключают, и тогда он не поймает
настоящее нарушение. Оба случая закреплены тестами.

## 12. Слой релизов — модуль `release`

Концепция: [`gld/gold.md §3`](../../gld/gold.md). Обход кода перед правкой:
[`docs/BLAST.md`](docs/BLAST.md:1).

| ID | Требование | Критерий готовности | Статус |
|---|---|---|---|
| REQ-REL-LAYOUT | `releases/<id>/` неизменяемы, состояние в `shared/`, внутрь релиза оно приходит junction | снятие указателя не удаляет данные цели | done |
| REQ-REL-SWAP | Установка — перевод `live`; откат — та же операция в обратную сторону | путь назад появляется до перевода указателя | done |
| REQ-REL-PIN | `APP_ROOT = realpath()` один раз при старте (INV-13) | переустановка указателя не меняет релиз работающего процесса | done |

**Состояние не движется — движется указатель.** Прежняя схема обновления переносила
`state/` и `prompts/` при каждой установке, и каждый перенос — шанс потерять то, что
человек писал руками. Здесь состояние физически не участвует: оно лежит в `shared/`,
а релиз видит его через junction. Откат становится переустановкой указателя, и вопрос
«где мои промпты» не может возникнуть.

**Что проверено на живой системе до написания кода.** `mklink /J` работает без прав
администратора; запись через указатель доходит до цели; `rmSync` без `recursive`
снимает ссылку, не трогая данные; настоящий каталог на месте указателя удалять
отказываемся. Последнее важно: `rmSync(recursive: true)` на junction в некоторых
версиях Node удалял содержимое цели — то есть снёс бы все промпты.

**INV-13 подтверждён отдельной пробой.** Работающий процесс, переживший
переустановку указателя, продолжает читать свой релиз; процесс, запущенный после,
видит новый; состояние у обоих общее. Без пина процесс читал бы файлы из двух
релизов одновременно — дефект, который проявляется случайно и ловится месяцами.

## 14. Геометрия UI — машинный контракт

Появление [`tests/e2e/geometry.mjs`](../tests/e2e/geometry.mjs:1) — не «ещё один
набор тестов». Это изменение формы спеки. До него контракт отвечал, что данные
верны и состояние названо, но не отвечал, где именно элемент находится и влезает ли
он в окно. Поэтому владелец видел сломанное, а гейт оставался зелёным.

### Словарь

- **полоса** — один контейнер, элементы внутри в одну строку;
- **ряд** — одинаковый `boundingBox.y` с точностью до 1px;
- **столбец** — одинаковый `boundingBox.x` с точностью до 1px;
- **переполнение** — `scrollWidth > clientWidth + 1` или `scrollHeight > clientHeight + 1`
  у контейнера, который не предназначен для собственной прокрутки;
- **обрезание** — переполнение интерактивного элемента или текст в контейнере с
  `overflow: hidden/clip` без `title`/подсказки;
- **перекрытие** — `elementFromPoint` в центре интерактивного элемента возвращает
  чужой узел;
- **цель нажатия** — кнопка/поле высотой не меньше 32px; навигационная ссылка и
  пункт меню могут быть частью общей строки меньшей высоты.

### Именованные инварианты

| ID | Утверждение | Реализация |
|---|---|---|
| I1 | контейнеры не обрезают содержимое | `noOverflow()` |
| I2 | интерактивный элемент в окне, не перекрыт, текст не обрезан, цель ≥32px | `notClippedOrOccluded()` |
| I3 | у `body` нет горизонтального скролла | `noPageScroll()` |
| I4 | открытая панель целиком видима вместе с кнопками | `overlayFits()` |
| I5 | горизонтальная полоса = один ряд с одинаковым `y` | `singleRow()` |
| I6 | компонент-полоса существует ровно один раз | `exactlyOne()` |
| I7 | действие не сбрасывает `scrollTop` списка | `scrollKept()` |
| I8 | пустое состояние сохраняет высоту и видимый плейсхолдер | `emptyKeepsLayout()` |
| I9 | обрезанный текст имеет `title`/подсказку | `truncatedHasTitle()` |
| I10 | на экране нет `undefined`, `NaN`, `null`, `Infinity` | `noTechnicalText()` |

### Матрица

[`tests/e2e/geo-matrix.spec.mjs`](../tests/e2e/geo-matrix.spec.mjs:1) гоняет базовый
набор по 3 ширинам (800×600, 1280×800, 1920×1080), 2 лёгким объёмам (0 и 20),
2 темам и отдельно 200 промптам на каждой ширине. Всего 42 проверки; пустое
состояние проверяется отдельно на каждой ширине.

Полный перебор тем на 200 строках не повторяется: тема меняет цвета, а не размеры.
Это зафиксированное сокращение матрицы, не молчаливый пропуск.

### Правило изменения

UI-правка начинается с assertion в [`geometry.mjs`](../tests/e2e/geometry.mjs:1) или
контрактного теста, затем меняется CSS/HTML/JS. Любая формулировка «сделать
горизонтально», «не резать кнопки», «панель должна влезать» обязана иметь
машинный инвариант. Скриншоты — следующий слой, не замена геометрическим
утверждениям.

**Как это требование нашлось.** Оно жило в [`trace.csv`](trace.csv:1) с самого
начала, но в этой таблице его не было. Гейт трассы молчал, потому что проверял
только одно направление — «требование из спеки есть в трассе». Расхождение
всплыло на числах: 61 строка `done` в трассе против 60 в спеке. Проверка обратного
направления добавлена в [`gates/trace-check.mjs`](gates/trace-check.mjs:88), и она
немедленно назвала строку.

Односторонняя проверка выглядела полной, но пропускала худший случай: поведение
реализовано, покрыто тестом и работает, а требования к нему никто не
сформулировал. Человек читает спеку и не знает, что это обещано.

## 16. Инварианты, нарушение которых означает провал

1. Ни одна операция не теряет пользовательский текст без копии.
2. Журнал буфера не покидает машину.
3. Один битый файл не выводит из строя остальные.
4. Счётчики пишет программа, а не человек.
5. Статус в этом файле = результат прогона, а не намерение.
6. Пользователь выбирает вид сам; приложение не навязывает один вариант.
