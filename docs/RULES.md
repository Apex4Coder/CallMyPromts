# RULES — основополагающие правила CallMyPromts

> Статус: **действуют с 2026-09-05**. Версия 1.0.
> Эти правила выше любого другого документа проекта. При конфликте побеждает этот файл.

## 0. Снятие требования утверждения владельцем

Владелец снял ограничение «каждый контракт утверждается владельцем» **в момент создания
спеки**. Практическое следствие:

| Было в SpecKit | Действует здесь |
|---|---|
| контракт имеет статус «на согласование», реализация ждёт | контракт создан → сразу считается действующим |
| необратимое действие требует отдельного подтверждения владельца | агент выполняет автономно, кроме списка §0.1 |
| владелец выбирает вариант дизайна | реализуются **все** варианты, выбор переносится в настройки приложения |

Это не отменяет требования **обосновывать** решения. Снято подтверждение, а не
объяснение: каждое решение по-прежнему сопровождается причиной, потому что через месяц
причина забывается, а код остаётся.

### 0.1 Что остаётся под запретом даже при снятом подтверждении

Список короткий и закрытый:

1. Удаление или перезапись пользовательских данных без резервной копии рядом.
2. Запись в каталоги других приложений (`ClipClip\Saved Clips`, `%APPDATA%\espanso`).
3. Отправка чего-либо в сеть: репозитории, облака, телеметрия.
4. Изменение системных настроек Windows и автозапуска без явной команды.
5. Правка baseline-файлов гейтов вручную.

Причина: пункты 1–2 необратимы, пункт 3 выносит данные за пределы машины, пункт 4
влияет на систему целиком, пункт 5 уничтожает смысл гейта.

## 1. Единая система правды

Один факт живёт в одном месте. Карта источников:

| Что | Единственный источник | Кто читает |
|---|---|---|
| границы модулей и слои | [`arch.yaml`](arch.yaml:1) | `gates/arch-check.mjs` |
| требования и их статусы | [`docs/SPEC.md`](docs/SPEC.md:1) | `gates/trace-check.mjs` |
| схемы данных | [`docs/DATA-CONTRACTS.md`](docs/DATA-CONTRACTS.md:1) | `contracts/` |
| сущности и связи | [`docs/ENTITY-MAP.md`](docs/ENTITY-MAP.md:1) | человек, карта удара |
| контракт интерфейса и DOM-id | [`docs/UI-SPEC.md`](docs/UI-SPEC.md:1) | E2E-тесты |
| сценарии, включая плохие | [`docs/SCENARIOS.md`](docs/SCENARIOS.md:1) | E2E-тесты |
| связь требование → тест | [`trace.csv`](trace.csv:1) | `gates/trace-check.mjs` |
| текст промпта | файл `.md` в библиотеке | `library/` |
| метаданные промпта | frontmatter того же `.md` | `library/` |
| журнал буфера | `state/clipboard.db` | `clipboard/` |
| настройки | `state/settings.json` | `contracts/`, `ui/` |

Запрещено: второй парсер одного формата, вторая копия списка промптов, второе
определение состояний интерфейса. Дубликат — это два мнения, которые однажды разойдутся.

## 2. Тактика правок: корень → дерево → листья

Любое изменение идёт в этом порядке, и порядок проверяем:

```
КОРЕНЬ    arch.yaml, SPEC.md, DATA-CONTRACTS.md
          меняется первым; без этого правка листа не имеет основания
   ▼
ДЕРЕВО    contracts/, library/, clipboard/, rank/
          доменная логика; здесь появляется поведение
   ▼
ЛИСТЬЯ    server/, ui/, bridge/
          доставка наружу; здесь ничего не решается, только отображается
```

Практические следствия:

- новое поведение сначала описано в спеке, потом реализовано;
- если правка листа требует «немного» поменять корень — это признак, что задача
  сформулирована неверно, надо вернуться к корню;
- карта удара строится **до** правки, а не после поломки.

## 3. Чанки и сущности

| Ограничение | Значение | Почему |
|---|---|---|
| файл | ≤ 300 строк | больше — теряется обзор, diff нечитаем |
| функция | ≤ 60 строк | больше — не удержать в голове целиком |
| строка | ≤ 400 знаков | минифицированный код невозможно править |
| вложенность | ≤ 3 уровня | глубже — сначала выделяем функцию |

Превышение не запрещено абсолютно: оно уходит в baseline и может только уменьшаться
(храповик долга, §7).

## 4. Честность данных

| Правило | Нарушение выглядит так |
|---|---|
| нет данных — прочерк и причина | `used: 0` там, где счётчик никогда не работал |
| статус только из проверки | зелёный узел без прогона |
| ошибка называет файл, строку и ожидание | «что-то пошло не так» |
| частичный успех — отдельное состояние | «готово» при 3 из 5 |
| счётчики считает программа, не человек | поле `used`, которое надо править руками |

Отдельно: **слово «готово» запрещено без `exit 0`** соответствующей проверки.

## 5. Интерфейс

| Правило | Источник |
|---|---|
| цвет не единственный носитель смысла: цвет + значок + слово | WCAG 2.2 SC 1.4.1 |
| контраст интерфейсных элементов ≥ 3:1 | WCAG 2.2 SC 1.4.11 |
| анимируются только `transform` и `opacity` | GPU-композитор; переносимость на слабые машины |
| `prefers-reduced-motion` уважается | WCAG 2.3.3 |
| ровно четыре состояния: `good ✓` `warn !` `bad ✕` `none –` | предел различимости |
| появление окна ≤ 200 мс | выше порога заметной задержки |
| вариант оформления выбирает пользователь в настройках | владелец отказался фиксировать один |

## 6. Приватность

Журнал буфера обмена содержит всё, что копировалось, включая пароли и токены.
Поэтому:

1. журнал **никогда** не синхронизируется и не покидает машину;
2. приложения-менеджеры паролей в чёрном списке по умолчанию;
3. в логах приложения не печатается содержимое записей, только их идентификаторы и длина;
4. `gates/secret-check.mjs` ищет секреты в коде проекта и роняет прогон;
5. HTTP API слушает только `127.0.0.1` и требует токен из `state/token`.

Пункт 5 обязателен: без токена любая страница в браузере смогла бы прочитать журнал
буфера через `fetch` на localhost.

## 7. Храповик долга

Порог «долг больше N — не принято» делает гейт красным с первой минуты, после чего его
отключают целиком. Поэтому долг замораживается в baseline и может **только падать**:

```
.arch-baseline.json    нарушения границ
.chunk-baseline.json   перерасход строк
.trace-baseline.json   требования без теста
```

Новый долг роняет прогон. Существующий — виден, но не блокирует. Править baseline
руками запрещено: их пишут только скрипты.

## 8. Тесты

| Уровень | Инструмент | Что доказывает |
|---|---|---|
| unit | `node --test` | поведение модуля, включая ошибочные входы |
| integration | `node --test` | связка модулей через публичные барьеры |
| e2e | **скрипты Playwright** (`npx playwright test`) | сквозной путь пользователя в реальном браузере |

E2E запускаются **скриптами из репозитория**, а не через интерактивный MCP-браузер.
MCP допускается только для разового просмотра внешней страницы во время разведки.

Каждый сценарий из [`docs/SCENARIOS.md`](docs/SCENARIOS.md:1) имеет и хороший, и плохой
путь. Тест, проверяющий только счастливый путь, считается неполным.

## 9. Автономность работы агента

- вопросы владельцу не задаются; неоднозначность решается в пользу более простого и
  обратимого варианта, решение записывается в документ с причиной;
- если вариантов несколько и все разумны — реализуются все, выбор уходит в настройки;
- при двух неудачных попытках подряд одним подходом подход меняется, а не подкручивается
  третий раз;
- временные файлы разведки удаляются после использования.

## 10. Язык и оформление

- документы, комментарии и сообщения интерфейса — по-русски;
- идентификаторы в коде — по-английски;
- комментарий объясняет **почему**, а не пересказывает код;
- кодировка UTF-8, переводы строк `\n`, отступ — два пробела в JS, четыре в Python.
