# DATA-CONTRACTS — схемы данных CallMyPromts

> Статус: **действует с 2026-09-05**. Версия 1.0.
> Назначение: убрать свободу трактовки перед реализацией. Кодер не угадывает формат,
> тестер не угадывает, что считать валидным.
> Требования: [`docs/SPEC.md §2`](docs/SPEC.md:1). Правила: [`docs/RULES.md`](docs/RULES.md:1).

## 0. Где что лежит

```
prompt-system/
├── prompts/                     ← ЕДИНСТВЕННАЯ библиотека, под git
│   ├── code/  core/  research/  parsing/  chatbox/  inbox/
│   └── *.md                     ← промпт = файл
├── state/                       ← НЕ под git, локальное состояние
│   ├── clipboard.db             ← журнал буфера (SQLite)
│   ├── settings.json            ← настройки
│   ├── token                    ← токен API, 32 hex-символа
│   └── runtime.json             ← порт, pid, время старта
└── backup/                      ← копии перед необратимыми операциями
    └── YYYY-MM-DD-HHMMSS/
```

`state/` в `.gitignore` целиком. Причина: журнал буфера содержит пароли
([`RULES §6`](docs/RULES.md:1)), а токен — секрет.

## 1. Промпт: файл `.md`

### 1.1 Структура файла

```markdown
---
id: c-review
title: Ревью кода
group: code
pin: 1
hotkey: "^!r"
trigger: ":c-review"
status: active
version: 2
created: 2026-08-07
updated: 2026-09-05
used: 12
last_used: 2026-09-05T18:42:00Z
score: 4
tags: [review, quality]
source: "anthropic-prompt-engineering"
---

Проведи ревью кода ниже.

Разбери по уровням, каждый отдельно:
1. Корректность — что сломается на реальных данных.
```

Тело — всё после закрывающего `---`. В приложение и в буфер уходит **только тело**.

### 1.2 Схема frontmatter

| Поле | Тип | Обязательно | Правило | По умолчанию |
|---|---|---|---|---|
| `id` | string | да | `^[a-z][a-z0-9-]{1,39}$`, уникален по библиотеке | имя файла без `.md` |
| `title` | string | да | 1..60 знаков, не пустая после trim | — |
| `group` | string | да | `^[a-z][a-z0-9-]{1,23}$`, совпадает с именем папки | из пути |
| `pin` | integer \| null | да как ключ | 1..9, уникален среди закреплённых | `null` |
| `hotkey` | string \| null | нет | синтаксис AHK: `^!r`, `+#q` | `null` |
| `trigger` | string \| null | нет | `^:[a-z][a-z0-9-]{1,23}$` | `null` |
| `status` | enum | да | `active` \| `draft` \| `archived` | `active` |
| `version` | integer | да | ≥ 1 | `1` |
| `created` | date | да | `YYYY-MM-DD` | дата создания файла |
| `updated` | date | да | `YYYY-MM-DD`, ≥ `created` | дата записи |
| `used` | integer | да | ≥ 0, **пишет только программа** | `0` |
| `last_used` | datetime \| null | да как ключ | ISO 8601 UTC, **пишет только программа** | `null` |
| `score` | integer \| null | нет | 1..5 | `null` |
| `tags` | list\<string\> | нет | каждый `^[a-z][a-z0-9-]{1,23}$` | `[]` |
| `source` | string \| null | нет | ≤ 120 знаков | `null` |

### 1.3 Правила валидации

| id | Проверка | Уровень | Почему |
|---|---|---|---|
| `V-P-1` | frontmatter существует и закрыт вторым `---` | bad | без метаданных промпт не отличить от заметки |
| `V-P-2` | `id` уникален по всей библиотеке | bad | дубликат делает поведение зависящим от порядка чтения |
| `V-P-3` | `title` не пуст | bad | в списке нужна читаемая строка; это лечит имена вида «первые 50 символов» |
| `V-P-4` | `pin` уникален среди `status: active` | bad | две «позиции 3» ломают моторную память |
| `V-P-5` | `hotkey` уникален по библиотеке | warn | конфликт решается в настройках, не блокирует |
| `V-P-6` | `trigger` уникален по библиотеке | warn | триггеры — опциональный канал |
| `V-P-7` | `group` совпадает с папкой | warn | автоисправляется при чтении, папка главнее |
| `V-P-8` | тело не пусто после очистки | bad | пустой промпт вставит пустоту |
| `V-P-9` | `updated` ≥ `created` | warn | хронология |
| `V-P-10` | тело не содержит `<html`, `<p ` , `style=` — **или** очистка сняла разметку | warn | признак непереваренного HTML-клипа |
| `V-P-11` | тело не начинается с `TODO:` — **или** очистка сняла этот префикс | warn | заглушка попадёт в чат |
| `V-P-12` | размер файла ≤ 256 КБ | bad | защита от случайного бинарника |

**Уровень `bad` изолирует только этот файл** ([`REQ-LIB-ISOLATE`](docs/SPEC.md:1)):
файл помечается `✕`, причина показывается, остальные продолжают работать. Это прямая
замена дефекта, при котором один пустой `.md` ломал все 26 триггеров.

### 1.4 Очистка тела перед выдачей

Порядок операций фиксирован:

1. отрезать frontmatter;
2. если тело выглядит как HTML (`<html`, `<body`, `<p ` в первых 200 знаках) — снять
   теги, раскрыть HTML-сущности, свернуть повторные пробелы, сохранить переводы строк
   между блоками;
3. снять префикс `TODO:` вместе с пробелом после него;
4. `trim` по краям;
5. нормализовать переводы строк в `\n`.

Причина шага 2: 19 из 39 клипов ClipClip — HTML с инлайн-CSS от Google Docs.

**Очистка идёт ДО валидации, и это меняет форму двух правил.** Валидатор получает
текст без тегов, поэтому проверка «тело похоже на HTML» по самому тексту на пути
чтения не срабатывает никогда: [`readPromptFile()`](library/read.mjs:106) вызывает
`cleanBody` строкой выше `validatePrompt`. Правила `V-P-10` и `V-P-11` поэтому
срабатывают и по факту очистки — `cleanBody().changed` передаётся в валидатор полем
`ctx.cleaned`.

Формулировка замечания при этом другая по смыслу. «Разметка попадёт в чат» после
очистки — неправда: в чат уйдёт чистый текст. Правда в том, что **разметка осталась
в файле** и снимается при каждом чтении, поэтому сообщение говорит именно это.
Уровень остаётся `warn`: промпт рабочий, чинить файл не обязательно.

`trim` в этот список не входит сознательно: лишние пустые строки по краям не меняют
смысл текста, и предупреждение о них было бы шумом на половине библиотеки.

### 1.5 Что запрещено изменять программе

`title`, `body`, `tags`, `source`, `score` — правит человек. Программа пишет только
`used`, `last_used`, `updated`, и `pin` — по явной команде пользователя.

Причина: разведка показала, что `fill.py` перезаписывал тело целиком, потому что нашёл
в нём слово `TODO`. Гарантия «программа не трогает текст» должна быть механизмом.

## 2. Журнал буфера: SQLite

### 2.1 Схема

```sql
CREATE TABLE IF NOT EXISTS clips (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  hash        TEXT    NOT NULL,               -- sha256 от text, для дедупликации
  kind        TEXT    NOT NULL,               -- text|url|code|path|email|image
  text        TEXT    NOT NULL,               -- полное содержимое
  preview     TEXT    NOT NULL,               -- первые 160 знаков, одна строка
  bytes       INTEGER NOT NULL,
  lines       INTEGER NOT NULL,
  source_app  TEXT,                           -- имя процесса-источника, если известно
  created_at  TEXT    NOT NULL,               -- ISO 8601 UTC
  promoted_to TEXT                            -- id промпта, если сохранён
);

CREATE INDEX IF NOT EXISTS idx_clips_created ON clips(created_at DESC);
CREATE INDEX IF NOT EXISTS idx_clips_hash    ON clips(hash);

CREATE TABLE IF NOT EXISTS meta (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
```

`meta` хранит `schema_version` — миграция без него превращается в угадывание.

### 2.2 Правила журнала

| id | Правило | Значение |
|---|---|---|
| `V-C-1` | новое сверху | сортировка `created_at DESC` |
| `V-C-2` | лимит | по умолчанию 100, диапазон 20..1000 |
| `V-C-3` | вытеснение | при превышении удаляется старейшая запись, у которой `promoted_to IS NULL` |
| `V-C-4` | дедупликация | если `hash` совпадает с **самой верхней** записью — не создаём вторую |
| `V-C-5` | минимальная длина | текст короче 2 знаков не записывается |
| `V-C-6` | максимальная длина | текст длиннее 1 МБ обрезается, факт обрезки помечается |
| `V-C-7` | чёрный список | запись из процесса из списка не создаётся |
| `V-C-8` | `preview` | одна строка, переводы строк заменены на `·`, обрезка по 160 знакам |

`V-C-3` защищает сохранённые записи: то, что уже стало промптом, не вытесняется молча.

`V-C-4` сверяет только с верхней записью, а не со всей таблицей: ClipClip ведёт себя
так же («Последний клип с такими данными уже существует»), и это правильно — повтор
через час осмысленен, повтор подряд нет.

### 2.3 Определение типа

Порядок проверок важен: первое совпадение выигрывает.

| Порядок | `kind` | Признак |
|---|---|---|
| 1 | `image` | содержимое буфера — растр, не текст |
| 2 | `url` | одна строка, начинается с `http://` или `https://` |
| 3 | `email` | одна строка, соответствует `^[^@\s]+@[^@\s]+\.[a-z]{2,}$` |
| 4 | `path` | одна строка, `^[a-zA-Z]:\\` или `^\\\\` или `^/` и без пробелов в начале |
| 5 | `code` | ≥ 2 строк и ≥ 2 признаков: `{`, `}`, `;`, `=>`, `def `, `function `, `import `, отступ в 2/4 пробела |
| 6 | `text` | всё остальное |

Тип — подсказка для значка и фильтра, не жёсткая гарантия. Ошибка классификации не
влияет на сохранность данных.

### 2.4 Чёрный список по умолчанию

```
keepass, keepassxc, bitwarden, 1password, lastpass, dashlane,
enpass, protonpass, nordpass
```

Сравнение по подстроке в имени процесса, регистр не учитывается. Список правится
в настройках. Причина: буфер менеджера паролей содержит сам пароль.

## 3. Настройки: `state/settings.json`

### 3.1 Схема

```json
{
  "schema_version": 1,
  "ui": {
    "layout": "hybrid",
    "theme": "system",
    "motion": "full",
    "accent": "teal",
    "density": "normal",
    "font_scale": 100,
    "show_badges": true,
    "show_temperature": true,
    "show_groups": true,
    "show_preview": true,
    "position": "center"
  },
  "order": {
    "mode": "pinned-frequency",
    "suggest_pin_after": 5
  },
  "clipboard": {
    "enabled": true,
    "limit": 100,
    "save_text": true,
    "save_images": false,
    "clear_on_exit": false,
    "blacklist": ["keepass", "bitwarden", "1password"]
  },
  "hotkeys": {
    "open_picker": "^!q",
    "save_clip": "^+s",
    "open_clips": "^!v",
    "toggle_watch": ""
  },
  "server": {
    "port": 8791
  },
  "library": {
    "path": "prompts"
  }

```

### 3.2 Допустимые значения

| Ключ | Значения | По умолчанию | Почему такое умолчание |
|---|---|---|---|
| `ui.layout` | `palette` \| `panels` \| `hybrid` | `hybrid` | быстро по умолчанию, подробно по Space |
| `ui.theme` | `light` \| `dark` \| `system` | `system` | не спорим с системой |
| `ui.motion` | `full` \| `reduced` \| `off` | `full` | владелец просил анимации |
| `ui.accent` | `teal` \| `indigo` \| `amber` \| `rose` \| `slate` | `teal` | `#006666` из SpecKit; не красный и не зелёный — они заняты статусами |
| `ui.density` | `compact` \| `normal` \| `comfortable` | `normal` | — |
| `ui.font_scale` | 100..200 | `100` | как в ClipClip |
| `ui.position` | `center` \| `cursor` \| `top` | `center` | владелец: «появляется в центре, где курсор» — оба варианта доступны |
| `order.mode` | `pinned-frequency` \| `manual` | `pinned-frequency` | ClipClip даёт оба, не решает за пользователя |
| `clipboard.limit` | 20..1000 | `100` | запрошено владельцем |
| `clipboard.save_images` | boolean | `false` | картинки раздувают базу, польза для промптов нулевая |
| `server.port` | 1024..65535 | `8791` | не 8790 — он занят панелью SpecKit |

### 3.3 Правила

| id | Правило |
|---|---|
| `V-S-1` | неизвестный ключ — ошибка с указанием пути к ключу, не тихое игнорирование |
| `V-S-2` | значение вне диапазона — ошибка с указанием допустимого диапазона |
| `V-S-3` | отсутствующий ключ заполняется значением по умолчанию и это записывается в лог |
| `V-S-4` | файл битый — берутся значения по умолчанию, битый файл переименовывается в `settings.broken.json` |
| `V-S-5` | пустая строка в `hotkeys.*` означает «не назначено» |

`V-S-4` важен: приложение, которое не стартует из-за одной опечатки в настройках,
хуже приложения с настройками по умолчанию.

## 4. Состояние сервиса: `state/runtime.json`

```json
{
  "pid": 24680,
  "port": 8791,
  "started_at": "2026-09-05T20:15:00Z",
  "library_path": "C:\\...\\prompt-system\\prompts",
  "hotkeys": {
    "open_picker":  { "combo": "^!q", "state": "good" },
    "save_clip":    { "combo": "^+s", "state": "good" },
    "open_clips":   { "combo": "^!v", "state": "bad", "reason": "занята другим приложением" },
    "toggle_watch": { "combo": "",    "state": "none", "reason": "не назначена" }
  }
}
```

Файл пишет только сервис. Используется для проверки «уже запущен»
([`REQ-SVC-GUARD`](docs/SPEC.md:1)) и для отображения светофора.

Поле `state` — одно из четырёх значений [`RULES §5`](docs/RULES.md:1), и при `bad`/`warn`
поле `reason` **обязательно**: статус без причины бесполезен.

## 5. Токен API: `state/token`

32 шестнадцатеричных символа, генерируется при первом старте из
`crypto.randomBytes(16)`. Передаётся заголовком `X-Deck-Token`.

Интерфейс получает токен не из файла, а подстановкой в HTML при отдаче страницы —
браузер не имеет доступа к файловой системе.

Причина существования токена: без него любая открытая веб-страница смогла бы прочитать
журнал буфера обмена запросом `fetch('http://127.0.0.1:8791/api/clips')`.

## 6. Формат ошибок

Единый для всех модулей:

```json
{
  "error": "invalid_frontmatter",
  "message": "поле title пусто",
  "file": "prompts/code/c-review.md",
  "line": 3,
  "expected": "строка 1..60 знаков"
}
```

Обязательны `error` и `message`. `file`, `line`, `expected` — когда применимы.
Ошибка без указания места превращает отладку в поиск наугад.

## 7. Парсер: одно подмножество YAML на проект

Понимает ровно это:

```yaml
key: значение
key: "значение в кавычках"
key: 123
key: true
key: null
key: [a, b, c]
```

Не поддерживается: вложенные карты внутри frontmatter, многострочные скаляры
(`|`, `>`), anchors и aliases, списки объектов. Нарушение — ошибка с номером строки.

Причина ограничения: frontmatter промпта плоский по схеме §1.2, а второй полноценный
YAML-парсер стал бы вторым мнением о формате ([`RULES §1`](docs/RULES.md:1)).
Настройки хранятся в JSON именно потому, что они вложенные.
