# SCENARIOS — сценарии работы, хорошие и плохие пути

> Статус: **действует с 2026-09-05**. Версия 1.0.
> Каждый сценарий имеет счастливый путь и минимум один плохой. Тест, проверяющий только
> счастливый путь, считается неполным ([`RULES §8`](docs/RULES.md:1)).
> Идентификатор `S-*` используется в [`trace.csv`](trace.csv:1) и в именах тестов.

## Как читать

```
S-XX   идентификатор сценария
цель   зачем пользователь это делает
путь   шаги
ждём   наблюдаемый результат
плохо  что может пойти не так и как система обязана себя вести
```

Плохой путь — не «покажем ошибку», а конкретное поведение с сохранением данных.

## S-01 · Вставить промпт по горячей клавише

**Цель.** Нужен промпт в чате, помнить триггер не хочу.

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | курсор в поле ввода чата | — |
| 2 | `Ctrl+Alt+Q` | окно видно ≤ 200 мс, фокус в поиске, список показан сразу |
| 3 | `1` | текст промпта вставлен в чат, окно закрылось |
| 4 | — | `used` вырос на 1, `last_used` обновлён |

**Плохие пути:**

| Что случилось | Обязательное поведение |
|---|---|
| сервер не запущен | окно не открывается, трей показывает `is-none` «сервис остановлен»; ничего не вставляется |
| библиотека пуста | окно открылось, `pickerEmpty`: «промптов нет — создайте первый через Ctrl+Shift+S» |
| выбранный промпт битый (`V-P-8`) | строка помечена `✕`, вставка заблокирована, причина видна в превью |
| буфер обмена занят другим процессом | повтор 3 раза с задержкой 50 мс, затем `toast` «не удалось получить буфер»; окно остаётся |
| целевое окно не принимает `Ctrl+V` | текст остаётся в буфере, `toast` «текст в буфере — вставьте вручную» |
| Punto Switcher перехватил хук | при старте хоткей не зарегистрировался → `is-bad` с именем перехватчика |
| промпт содержит только пробелы | `V-P-8` считает тело пустым → `✕`, не вставляем пустоту |

## S-02 · Найти промпт поиском

**Цель.** 26 промптов, номер не помню, помню слово.

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | `Ctrl+Alt+Q` | окно открыто |
| 2 | ввести «ревью» | список сузился, совпадение подсвечено |
| 3 | `Enter` | первый результат вставлен |

**Плохие пути:**

| Что случилось | Поведение |
|---|---|
| забыта раскладка, набрано «htdm» | поиск переводит по физическим клавишам в «ревь» и находит «Ревью кода» |
| нет совпадений | `is-none`: «ничего не найдено по запросу «…»», список пуст, но окно живо |
| запрос из одного символа | ищем, но не по телу — только по названию и группе, иначе выдача бессмысленна |
| запрос длиннее 200 знаков | обрезаем до 200, факт обрезки не скрываем |
| в запросе символы регулярного выражения | трактуются буквально, не как шаблон |
| нажат `1` при непустом поиске | это ввод символа, не выбор позиции ([`UI-SPEC §4`](docs/UI-SPEC.md:1)) |

## S-03 · Сохранить выделенный текст как промпт

**Цель.** Увидел хороший текст, хочу в библиотеку, не выходя из потока.

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | выделить текст | — |
| 2 | `Ctrl+Shift+S` | диалог: поле имени, выпадающий список групп |
| 3 | ввести имя, выбрать группу | — |
| 4 | `Enter` | файл `.md` создан, `pin` не назначен, промпт виден в списке без перезапуска |

**Плохие пути:**

| Что случилось | Поведение |
|---|---|
| ничего не выделено | берём текущее содержимое буфера; если и он пуст — `toast` «нечего сохранять» |
| имя пусто | `Enter` не срабатывает, поле помечено, подсказка «нужно имя 1..60 знаков» |
| имя содержит `\ / : * ? " < > |` | символы заменяются на `-`, пользователю показано итоговое имя файла |
| файл с таким `id` уже есть | предлагается `id-2`; перезапись невозможна без явного подтверждения |
| выбрана новая группа | папка создаётся, имя приводится к `^[a-z][a-z0-9-]{1,23}$` |
| текст — HTML из Google Docs | разметка снята по [`DATA-CONTRACTS §1.4`](docs/DATA-CONTRACTS.md:1) |
| текст 5 МБ | `V-P-12` отвергает > 256 КБ: «слишком большой для промпта», запись остаётся в журнале |
| папка библиотеки только для чтения | `toast` с путём и причиной; запись не теряется — остаётся в журнале буфера |
| диск заполнен | то же; сначала пишем во временный файл, потом переименовываем |

Запись во временный файл с последующим переименованием — защита от половинчатого файла
при сбое. Это требование [`REQ-LIB-SAFE`](docs/SPEC.md:1).

## S-04 · Журнал буфера: достать старую запись

**Цель.** Копировал полчаса назад, теперь нужно снова.

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | `Ctrl+Alt+V` | журнал, новое сверху, счётчик «87 из 100» |
| 2 | найти запись глазами или поиском | — |
| 3 | правый клик | меню из трёх пунктов |
| 4 | «Копировать» | содержимое в буфере, `toast` «скопировано» |

**Плохие пути:**

| Что случилось | Поведение |
|---|---|
| журнал пуст | «записей нет — слежка включена, скопируйте что-нибудь» |
| слежка на паузе | `is-warn` «слежка приостановлена» + кнопка возобновления |
| база повреждена | база переименована в `clipboard.broken.db`, создана новая, пользователь предупреждён |
| запись — картинка | показывается размер, «копировать» возвращает картинку, «сохранить как промпт» недоступно |
| текст записи 900 КБ | в списке `preview` 160 знаков; полный текст только по требованию |
| 100 записей, копируется 101-я | вытесняется старейшая **без** `promoted_to`; сохранённые не трогаем (`V-C-3`) |
| скопировано трижды подряд одно и то же | одна запись (`V-C-4`) |
| копирование из менеджера паролей | запись не создаётся (`V-C-7`), в логе только факт пропуска без содержимого |

## S-05 · Превратить запись журнала в промпт

**Цель.** В буфере оказался хороший текст — хочу закрепить навсегда.

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | правый клик по записи | меню |
| 2 | «Сохранить как промпт ▸» | подменю со списком групп и «+ Новая группа» |
| 3 | выбрать группу | поле имени |
| 4 | `Enter` | файл создан, `promoted_to` записан в журнал |

**Плохие пути:**

| Что случилось | Поведение |
|---|---|
| групп нет вовсе | подменю показывает только «+ Новая группа» |
| та же запись сохраняется второй раз | предупреждение «уже сохранена как «…»» + возможность создать копию |
| после создания промпт битый по схеме | файл создан, помечен `✕`, причина показана; запись в журнале не удаляется |

## S-06 · Закрепить промпт на позицию

**Цель.** Постоянно нужен один промпт — хочу его под цифрой.

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | окно выбора, промпт выделен | — |
| 2 | контекстное действие «Закрепить» | предлагается первая свободная позиция 1..9 |
| 3 | подтвердить | `pin` записан, позиция стабильна между запусками |

**Плохие пути:**

| Что случилось | Поведение |
|---|---|
| все 9 позиций заняты | «свободных позиций нет», предлагается заменить: показано, что уйдёт с позиции |
| выбрана занятая позиция | обмен местами, оба файла обновлены; молчаливой перезаписи нет |
| `pin` дублируется после ручной правки файла | `V-P-4` → оба помечены `!`, порядок по `id` до исправления |
| промпт в `status: archived` | закрепление запрещено, причина названа |

## S-07 · Настроить горячие клавиши

**Цель.** `Ctrl+Q` занят ClipClip — хочу свою комбинацию.

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | окно управления → «Хоткеи» | текущие комбинации и их состояния |
| 2 | клик по полю, нажать сочетание | комбинация записана в поле |
| 3 | «Применить» | попытка регистрации, результат сразу виден |

**Плохие пути:**

| Что случилось | Поведение |
|---|---|
| комбинация занята другим приложением | поле красное `✕`, имя перехватчика, если определимо; предложены свободные |
| комбинация уже назначена внутри приложения | конфликт показан до применения |
| нажата одиночная клавиша без модификатора | отказ: «нужен минимум один модификатор» |
| нажата системная (`Ctrl+Alt+Del`, `Win+L`) | отказ с объяснением |
| поле очищено | «не назначено», `is-none`, функция доступна только из окна |
| регистрация упала без причины | `is-bad` + `reason`, остальные хоткеи продолжают работать |
| AHK не установлен | `is-bad` «AutoHotkey не найден», окно управления работает, хоткеев нет |

Ключевой принцип, взятый у ClipClip: **красная строка вместо тихого отказа**. Хуже
всего вариант, когда клавиша не работает и никто не сказал почему.

## S-08 · Остановить и запустить сервис

**Цель.** Мешает — хочу выключить, не удаляя.

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | трей → «Остановить» | хоткеи снимаются, слежка прекращается, `runtime.json` удалён |
| 2 | трей → «Запустить» | сервер поднят, хоткеи зарегистрированы, состояния обновлены |

**Плохие пути:**

| Что случилось | Поведение |
|---|---|
| порт занят | пробуем следующий свободный, сообщаем какой занят и какой взят |
| второй запуск приложения | второй процесс не создаётся, показывается окно первого (`REQ-SVC-GUARD`) |
| `runtime.json` остался от аварийно завершённого процесса | pid проверяется; мёртвый — файл перезаписывается |
| остановка во время записи в базу | транзакция завершается, потом остановка |

## S-09 · Сменить оформление

**Цель.** Хочу тёмную тему и другую раскладку.

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | «Вид» | все опции из [`UI-SPEC §3.3`](docs/UI-SPEC.md:1) |
| 2 | тема «тёмная», раскладка «panels» | применяется сразу, без перезагрузки |
| 3 | закрыть и открыть окно | настройки сохранились |

**Плохие пути:**

| Что случилось | Поведение |
|---|---|
| `settings.json` битый | берутся значения по умолчанию, битый файл → `settings.broken.json`, пользователь предупреждён (`V-S-4`) |
| неизвестный ключ в файле | ошибка с путём к ключу, не тихое игнорирование (`V-S-1`) |
| значение вне диапазона | ошибка с допустимым диапазоном (`V-S-2`) |
| системное `prefers-reduced-motion` включено | уровень движения понижен принудительно, в интерфейсе объяснено почему |
| `font_scale` = 200 при окне 640px | раскладка не ломается: перенос строк, без горизонтального скролла |

## S-10 · Правка промпта

**Цель.** Промпт устарел.

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | окно выбора, `F2` | правка: имя, группа, текст |
| 2 | изменить, сохранить | `updated` обновлён, `used`/`score`/`version` сохранены |
| 3 | окно выбора | новый текст виден сразу, без пересборки |

**Плохие пути:**

| Что случилось | Поведение |
|---|---|
| файл изменён извне во время правки | сравнение времени изменения; при расхождении предлагается выбор, перезаписи молча нет |
| текст стёрт полностью | сохранение заблокировано: `V-P-8` |
| файл удалён извне | «файл исчез», предлагается создать заново из введённого текста |
| сохранение упало | исходный файл цел: пишем во временный и переименовываем |
| нужен внешний редактор | «Открыть в VS Code» открывает файл, приложение подхватывает изменения |

## S-11 · Миграция трёх копий библиотеки

**Цель.** Свести `~/prompts`, `prompt-system/prompts` и 22 клипа ClipClip в одну папку.

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | `node legacy/migrate.mjs --report` | таблица: файл, три версии, какая новее, что потеряется; **ничего не пишется** |
| 2 | `node legacy/migrate.mjs --apply` | резервная копия всех источников, затем слияние |
| 3 | проверка | ноль расхождений, имена читаемые, `.html` очищен |

**Плохие пути:**

| Что случилось | Поведение |
|---|---|
| источник недоступен | пропускаем, называем какой и почему; остальные обрабатываем |
| одинаковый `id` в двух источниках | берём с более поздним `updated`; вторая версия сохраняется как `<id>.conflict.md` |
| у клипа нет пригодного имени | имя из первых 3 значимых слов, помечается `!` для ручной вычитки |
| в клипе только HTML-мусор | после очистки тело пусто → в `inbox/`, не в библиотеку |
| `--apply` без предварительного `--report` | отказ: сначала отчёт |
| резервная копия не создалась | миграция не начинается |

## S-12 · Проверка целостности

**Цель.** Понять, всё ли в порядке.

| Шаг | Действие | Ожидание |
|---|---|---|
| 1 | «Диагностика» → «Проверить» | список проверок: значок, название, объяснение |
| 2 | — | проблемные строки ведут к причине |

Проверяется: путь библиотеки, число промптов, битые файлы, дубли `id` и `pin`, состояние
базы журнала, регистрация хоткеев, наличие AHK, порт, права на запись.

**Плохой путь:** ни одна проверка не «зелёная по умолчанию». Не удалось проверить —
`is-none` с причиной, а не `is-good`.
